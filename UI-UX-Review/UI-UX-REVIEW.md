# UI/UX Review

This review documents visual and usability observations identified during testing of the EchoChat application and extension. These observations are provided as improvement suggestions rather than functional defects.

| ID | Screen / Area | UI/UX Observation | Recommendation | Evidence |
|---|---|---|---|---|
| UX-001 | Sign-in | Layout could be better optimized for the larger Samsung Tab S6 screen. | Improve responsive spacing and alignment on larger screens. | [UX-001.png](../Evidence/UX-001.png) |
| UX-002 | History – Android | On Android, the History screen displayed incorrect timestamps for messages, with the recorded times not matching their actual sent times. | Consider ensuring that History timestamps consistently reflect the correct local time. | [UX-002.png](../Evidence/BUG-002-history-time.jpeg) |
| UX-003 | Settings / Profile – Chrome | On Chrome, both the Settings icon and the profile/name control open the same popup, which may make it unclear why two separate controls are provided. | Consider giving the two controls clearly distinct functions or combining them into a single control. | [UX-003.mp4](../Evidence/UX-003.mp4) |
| UX-004 | History / Response Actions – Chrome | On Chrome, response actions such as Copy and Retry are not shown when a conversation is reopened from History. | Consider keeping relevant response actions available when viewing saved conversations. | [UX-004.png](../Evidence/UX-004.png) |
| UX-005 | Response Actions – Android & Chrome | The available response actions vary between Android and Chrome, which may result in a slightly different experience across platforms. | Consider keeping the response-action experience consistent across supported platforms where possible. | [BUG-007-android-response-actions.jpeg](../Evidence/BUG-007-android-response-actions.jpeg)<br>[BUG-007-chrome-response-actions.jpeg](../Evidence/BUG-007-chrome-response-actions.jpeg) |
| UX-006 | Message Quota – Chrome & Android | On Chrome, the remaining message quota is not displayed while using the extension, whereas Android shows the remaining quota and reset information. On Chrome, users only receive a popup message after the quota has been reached. | Consider displaying the remaining message quota and reset information on Chrome before the limit is reached. | [BUG-008-android-quota-indicator.jpeg](../Evidence/BUG-008-android-quota-indicator.jpeg)<br>[BUG-008-chrome-quota-limit.jpeg](../Evidence/BUG-008-chrome-quota-limit.jpeg) |
| UX-007 | Screenshot Attachment – Chrome | In the Chrome Extension, the Screenshot/Scissors feature allows a PNG screenshot to be attached, but the file is rejected during processing because PNG is not supported. | Consider indicating the supported file formats before or when the screenshot is attached. | [BUG-012-screenshot-attachment-failure1.jpeg](../Evidence/BUG-012-screenshot-attachment-failure1.jpeg)<br>[BUG-012-screenshot-attachment-failure2.jpeg](../Evidence/BUG-012-screenshot-attachment-failure2.jpeg) |
| UX-008 | Shortcut Commands – Chrome | On Chrome, clicking the Shortcut Commands control shows no visible response, making its function unclear. | Consider displaying the available shortcut commands or providing clearer feedback when selected. | [BUG-011-shortcut-command-button.jpeg](../Evidence/BUG-011-shortcut-command-button.jpeg) |
| UX-009 | Registration – Chrome | On Chrome, the registration form shows a “First name is required” message even though there is no First Name field. | Consider aligning the validation message with the fields shown in the registration form. | [BUG-003-missing-first-name-field.jpeg](../Evidence/BUG-003-missing-first-name-field.jpeg) |
| UX-010 | Email Autocomplete – Chrome | On Chrome, email suggestions are displayed but cannot be selected, so the email address has to be entered manually. | Consider allowing users to select a displayed email suggestion directly. | [BUG-005-email-autocomplete.mp4](../Evidence/BUG-005-email-autocomplete.mp4) |
| UX-011 | Compare – AI Model Selection | In the Compare feature, AI models are displayed without indicating whether they are free or paid. | Consider clearly labeling models as free or paid to help users understand the available options before selecting them. | [UX-011.png](../Evidence/UX-011.png) |
| UX-012 | Connectors – Add Connector | The “0 connected” label is very close to the Add connector button, making the spacing appear crowded. | Consider adding more spacing between the label and the button for clearer separation. | [UX-012.png](../Evidence/UX-012.png) |
| UX-013 | Chat Input – Send Button | The Send button appears vertically misaligned with the Search option and the input hint text. | Consider aligning the elements within the chat input row for a more consistent layout. | [UX-013.png](../Evidence/UX-013.png) |
| UX-014 | Main Chat Screen | The main screen shows both tool shortcut cards and prompt suggestions, which can make the first screen feel crowded. | Consider simplifying or combining these sections to reduce visual clutter. | [UX-014.png](../Evidence/UX-014.png) |
| UX-015 | Model Selector – Information Text | The information text under the model selector is cut off, so the full message cannot be read. | Consider allowing the full text to be displayed or providing a way to view the complete message. | [UX-015.png](../Evidence/UX-015.png) |
