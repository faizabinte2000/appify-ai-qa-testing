# UI/UX Review

This review documents visual and usability observations identified during testing of the EchoChat application and extension. These observations are provided as improvement suggestions rather than functional defects.

| ID | Screen / Area | UI/UX Observation | Recommendation | Evidence |
|---|---|---|---|---|
| UX-001 | Sign-in | Layout could be better optimized for the larger Samsung Tab S6 screen. | Improve responsive spacing and alignment on larger screens. | [UX-001.png](../Evidence/UX-001.png) |
| UX-002 | History – Android | On Android, the History screen displayed incorrect timestamps for messages, with the recorded times not matching their actual sent times. | Consider ensuring that History timestamps consistently reflect the correct local time. | [UX-002.png](../Evidence/BUG-002-history-time.jpeg) |
| UX-003 | Settings / Profile – Chrome | On Chrome, the Settings icon and profile/name control currently lead to the same popup, so their purposes may not be immediately clear. | Consider differentiating the functions or presentation of these controls. | [UX-003.png](../Evidence/UX-003.png) |
| UX-004 | History / Response Actions – Chrome | On Chrome, some response actions available in the current conversation are not visible when the conversation is reopened from History. | Consider keeping relevant response actions available when viewing saved conversations. | [UX-004.png](../Evidence/UX-004.png) |
| UX-005 | Response Actions – Android & Chrome | The available response actions vary between Android and Chrome, which may result in a slightly different experience across platforms. | Consider keeping the response-action experience consistent across supported platforms where possible. | [UX-005.png](../Evidence/UX-005.png) |
| UX-006 | Message Quota – Chrome | On Chrome, the remaining message quota is not as visible as it is on Android. | Consider displaying the remaining quota and reset information more clearly in the extension. | [UX-006.png](../Evidence/UX-006.png) |
| UX-007 | Offline State – Android | On Android, the input and Send control remain visible while offline, which could make the current connection state less clear. | Consider providing clearer visual feedback when the app is offline or sending is unavailable. | [UX-007.png](../Evidence/UX-007.png) |
| UX-008 | Shortcut Commands – Chrome | On Chrome, selecting the Shortcut Commands control does not provide visible feedback, so its function may not be immediately apparent. | Consider displaying the available shortcut commands or providing clearer feedback when selected. | [UX-008.png](../Evidence/UX-008.png) |
| UX-009 | Screenshot Attachment – Android | On Android, a PNG screenshot can be selected before the file-format restriction becomes apparent. | Consider showing the supported attachment formats more clearly before or during file selection. | [UX-009.png](../Evidence/UX-009.png) |
| UX-010 | Registration – Android | On Android, the registration form displays a “First name is required” message even though a First Name field is not visible. | Consider aligning the validation message with the fields presented in the registration form. | [UX-010.png](../Evidence/UX-010.png) |
| UX-011 | Email Autocomplete – Android | On Android, email suggestions are displayed but do not appear to be directly selectable. | Consider allowing users to select a displayed email suggestion directly. | [UX-011.png](../Evidence/UX-011.png) |
