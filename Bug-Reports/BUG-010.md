# BUG-010 — Incorrect AI Model Attribution for Compare Responses in History

## Bug ID
BUG-010

## Title
History displays the currently selected AI model as the source of all Compare responses

## Description
When a conversation created using the **Compare** feature is saved and later reopened from **History**, the individual responses are displayed without retaining their original model attribution.

Instead, the History conversation displays the **currently selected AI model**, making it appear that the currently selected model generated all of the responses.

This behavior was observed on both the **Android App** and **Chrome Extension**.

## Steps to Reproduce
1. Open the **Compare** feature.
2. Select multiple AI models.
3. Enter a prompt.
4. Submit the prompt and wait for the selected models to generate their responses.
5. Verify that different models provide separate responses.
6. Navigate to the **History** section.
7. Open the saved Compare conversation.
8. Observe the model information displayed for the saved responses.
9. Compare the displayed model with the models that originally generated the responses.

## Expected Result
Each saved Compare response should retain and display the **AI model that originally generated that response**.

The model attribution should remain unchanged when the conversation is reopened from History, regardless of which model is currently selected.

## Actual Result
The individual Compare responses are displayed in History, but their original model attribution is not retained.

Instead, the **currently selected AI model is displayed**, making it appear that the currently selected model generated all of the responses, even though the responses were originally generated by different models.

The issue was observed on both the Android App and Chrome Extension.

## Notes
The Compare feature initially generates separate responses from the selected models. The incorrect attribution occurs when the saved Compare conversation is later viewed from History.

The issue can cause users to incorrectly associate a response with the currently selected model rather than the model that originally generated it.
